# Метрология M.A.R.S. без живых испытуемых

**Вопрос:** насколько точно M.A.R.S. измеряет асимметрию лица и согласуются ли его числа с оценкой врача?

**Ответ кратко:**
- Повторяемость высокая: минимальное различимое изменение (MDC95) — **0,1–0,5 мм**.
- Систематическая ошибка на идеально симметричном лице — до **±1 мм** между людьми.
- Изменения видны линейно, но в уменьшенном масштабе: **≈ 50 % у бровей и ≈ 60 % у углов рта**.
- На клиническом наборе MEEI индекс динамической асимметрии:
  - определяет сторону паралича в **82 %** случаев;
  - отличает пациентов от здоровых с **AUC 0,84**;
  - коррелирует с тяжестью по eFACE: **ρ = 0,83** при вялом параличе и **0,69** при синкинезии.

## 1. Методы

### 1.1 Цифровой фантом (точность, повторяемость, устойчивость)
Эталон известен точно, потому что создаётся программно (`metrology/phantom.py`).

1. **Симметричный фантом.** Берётся снимок здорового добровольца (анфас, покой) из набора MEEI. Снимок выравнивается по линии зрачков, одна половина лица отражается на другую. Истинная асимметрия равна 0.
2. **Заданная асимметрия.** Вся бровь или угол рта плавно сдвигаются вверх на 0,5–4 мм (гауссово поле смещений). Истинное изменение каждой метрики считается по формуле деформации.
3. **Одно измерение — как в приложении:** медиана по 12 кадрам в допуске позы 5°. Кадры — копии снимка со случайными мелкими искажениями:
   - шум сенсора, σ = 2,5;
   - яркость ±5 %;
   - JPEG 85–95;
   - сдвиг ±1 пиксель, масштаб ±1 %, поворот ±0,3°.

   На каждое условие делается 8 измерений.
4. **Плохие условия:** темно, пересвет, сильный шум, сжатие JPEG 35, межзрачковое расстояние (МЗР) 60 пикселей, наклон головы 6°.

Точки находит MediaPipe Face Landmarker с **той же моделью** `face_landmarker.task` (SHA-256 сверен), что и в браузере. Метрики считает `vision/metrics.py` — те же формулы, что в браузере. Снимки уменьшены до 1920 пикселей, как кадр камеры Full HD. Миллиметры = доли МЗР × 63 мм (средний МЗР взрослого). В приложении миллиметры считаются по калибровке.

### 1.2 Клиническая состоятельность (`metrology/meei.py`)
**Набор:** MEEI Facial Palsy Photo and Video Standard Set (Greene et al., *Laryngoscope* 2020; 130: 32–37).
- Снимки 8 движений.
- Категория тяжести по шкале eFACE, которую выставил врач.
- Сторона паралича.

Авторы выложили набор как открытую базу для исследований и обучения. Пациенты дали согласие на использование снимков в исследованиях. В репозитории нет ни одного снимка, только числа.

Числовых оценок House–Brackmann и Sunnybrook по отдельным пациентам в открытой таблице нет. Поэтому сравнение идёт с категорией тяжести по eFACE (норма, near normal, mild, moderate, severe, complete).

**План анализа зафиксирован в коде до первого запуска.**
- Амплитуда каждой стороны — смещение точек от покоя:
  - брови: подъём;
  - глаза: уменьшение глазной щели при сильном закрытии;
  - рот: смещение угла рта при широкой улыбке.
- Асимметрия движения: A = 1 − min/max.
- Индекс динамической асимметрии (ИДА) — среднее A по трём движениям.
- Основные показатели:
  - совпадение слабой стороны с записанной стороной паралича;
  - ρ Спирмена ИДА с тяжестью;
  - AUC «здоровые против пациентов».
- 95 % ДИ: по Уилсону для долей, бутстреп 2000 повторов для ρ и AUC.

## 2. Результаты

### 2.1 Повторяемость и систематическая ошибка
Симметричный фантом, 6 добровольцев. У 4 из 10 снимков после выравнивания поза вышла за допуск 5°, приложение такие снимки тоже не принимает.

| Метрика | Смещение нуля, мм (среднее ± SD между людьми) | Повторяемость SD, мм | MDC95, мм |
|---|---|---|---|
| Высота бровей | −0,19 ± 0,44 | 0,11 | 0,31 |
| Высота уголков рта | −0,29 ± 0,31 | 0,09 | 0,24 |
| Уголки рта до средней линии | 0,27 ± 1,08 | 0,18 | 0,51 |
| Внешние уголки глаз | 0,15 ± 0,35 | 0,11 | 0,31 |
| Внутренние уголки глаз | 0,07 ± 0,26 | 0,12 | 0,32 |
| Ширина половин лица | 0,20 ± 0,45 | 0,16 | 0,43 |
| Кончик носа | 0,02 ± 0,46 | 0,09 | 0,25 |
| Подбородок | −0,02 ± 0,89 | 0,13 | 0,36 |
| Наклон линии глаз | 0,21 ± 0,27° | 0,04° | 0,11° |

Откуда смещение нуля: на идеально зеркальном снимке MediaPipe ставит парные точки несимметрично на 1–4 пикселя, около 1 % МЗР. Больше всего ошибается центр зрачка по вертикали. Через центры зрачков приложение проводит опорную линию глаз, поэтому ошибка зрачков наклоняет линию и переходит в высоту бровей и уголков рта.

### 2.2 Чувствительность: измерено против истины

| Область | Истинное изменение, мм | Измерено, мм | Доля увиденного |
|---|---|---|---|
| Бровь | 0,40 / 0,80 / 1,60 / 2,40 / 3,20 | 0,20 / 0,40 / 0,80 / 1,18 / 1,51 | 47–51 % |
| Угол рта | 0,49 / 0,98 / 1,96 / 2,94 / 3,92 | 0,33 / 0,64 / 1,23 / 1,79 / 2,36 | 60–67 % |

Наклон регрессии: бровь 0,47 (R² = 0,82), угол рта 0,59 (R² = 0,94). Зависимость линейная, но масштаб занижен. MediaPipe подгоняет точки под типичную форму лица и частично сглаживает местные изменения.

### 2.3 Плохие условия съёмки

Наклон 6° приложение отбрасывает так, как и задумано: контроль позы не пропускает снимки вне допуска 5°.

### 2.4 Клинический набор MEEI
В анализ вошёл 41 человек из 51 (8 здоровых, 33 пациента). Остальные исключены, потому что поза хотя бы на одном снимке вышла за 10°. Чаще всего это широкая улыбка (7 из 10): при сильной мимике MediaPipe хуже оценивает поворот головы.

## 3. Выводы

1. **Повторяемость — сильная сторона.** MDC95 0,1–0,5 мм. Изменение больше 0,5 мм между двумя измерениями при одинаковой съёмке — не шум. Это нижняя граница: на живом человеке добавятся поза, мимика и свет.
2. **Асимметрию в покое меньше ~1 мм нельзя отличить от ошибки модели.** Смещение нуля между людьми — до ±1 мм. На клиническом наборе статика в покое отличает пациентов от здоровых слабо (AUC 0,41–0,72).
3. **Миллиметры по бровям и углам рта занижены примерно в 2 и 1,6 раза**, но линейно. Динамика у одного пациента видна правильно по направлению и пропорциям, а абсолютные миллиметры сравнивать с измерениями линейкой нельзя.
4. **Динамические метрики клинически состоятельны:** сторона в 82 % случаев, ρ = 0,83 с тяжестью по оценке врача. Лучше всего работает подъём бровей.
5. **Закрытие глаз по точкам век не работает** (AUC 0,51). При сильном закрытии веки смыкаются у всех, и разница в силе по точкам не видна.

## 4. Что улучшить в M.A.R.S. (по результатам)

1. **В отчёте врача помечать** статическую асимметрию меньше 1 мм как «в пределах погрешности системы». Миллиметры бровей и углов рта подписывать как относительные, пока нет проверки линейкой на живых людях.
2. **Главный показатель — динамический (ИДА).** Вынести его в отчёт рядом со статикой.
3. **Проверить опорную линию по внутренним уголкам глаз вместо центров зрачков.** Ошибка зрачков даёт основную часть смещения нуля. Это гипотеза, её надо проверить на том же фантоме.
4. **Закрытие глаз оценивать не по точкам век.** Кандидаты: показатель MediaPipe `eyeBlink` при мягком закрытии (снимок 3) или площадь глазной щели.

## 5. Ограничения

- Фантом — программная деформация снимка, а не настоящее сокращение мышц. Доля увиденного относится именно к такой деформации.
- Миллиметры пересчитаны из МЗР 63 мм, без калибровки.
- Снимки MEEI сделаны фотоаппаратом, а не веб-камерой. Точки найдены MediaPipe для Python 0.10.21 (в браузере 0.10.14) с той же моделью.
- Сравнение идёт с категорией по eFACE, а не с баллами HB и Sunnybrook. Выборка маленькая, из одного центра. Доверительные интервалы широкие.
- Повторяемость получена на фантоме и не заменяет повторных съёмок живого человека.

## Воспроизведение

```bash
vision/.venv/bin/python -m metrology.phantom     # ≈ 35 минут на Intel i5
vision/.venv/bin/python -m metrology.meei        # несколько минут
python3 metrology/summary.py                     # таблицы
vision/.venv/bin/python tests/test_metrology.py  # проверки расчётов
```

Набор MEEI кладётся в `datasets/meei/` (не входит в репозиторий). Как установить MediaPipe для Python на Mac с Intel: `SYSTEM_VERSION_COMPAT=0 pip install --only-binary=:all: mediapipe==0.10.21 sentencepiece==0.2.1` в `vision/.venv`.
