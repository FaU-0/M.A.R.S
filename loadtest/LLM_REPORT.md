# Обезличивание в M.A.R.S.: локальная Ollama против облачного GigaChat — мини-отчёт

## Задача

Заменить обработку через локальную нейросеть Ollama на облачный GigaChat API и сравнить:
1. скорость самой обработки;
2. общую финальную скорость работы приложения.

## Что сделано

- **Клиент GigaChat** (`assistant/gigachat.py`): вход по ключу авторизации, токен на 30 минут с обновлением заранее, повтор при «слишком много запросов» (429), ответ строго по JSON-схеме. Ключ берётся из окружения и никуда не записывается.
- **Выбор нейросети настройкой** `LLM_BACKEND=ollama|gigachat` (`assistant/main.py`). Запрос к модели одинаковый, отличается только исполнитель. По умолчанию — Ollama.
- **Исправление по ходу эксперимента** (`assistant/deid.py`): GigaChat ставит найденные слова в начальную форму («Кинешма» при «из Кинешмы»), а фильтр принимал только дословные совпадения и отбрасывал их. Теперь слово ищется в тексте в любой падежной форме и заменяется так, как написано в тексте.
- **Тесты** без сети: `tests/test_gigachat.py`, 33 проверки.

## 1. Скорость самого обезличивания

20 основных и 10 отложенных диалогов (с незнакомыми именами и городами), по одному прогону, только сервис обезличивания. Скрипт `loadtest/bench_llm.py`.

| | Ответ на фрагмент текста, медиана | p95 | Один диалог | Найдено имён и мест | Мед. слова сохранены | Лишние замены |
|---|---|---|---|---|---|---|
| Ollama `qwen2.5:3b` | 10,8 с | 28,0 с | 26,3 с | 98,8 % | 100 % | 1 |
| GigaChat-2-Max | 1,9 с | 4,5 с | 4,5 с | 96,2 % | 100 % | 0 |
| GigaChat-2 (Lite) | 1,2 с | 2,3 с | 2,5 с | 93,4 % | 100 % | 0 |

Сбоев: 0 из 60 запросов у каждого варианта. Токены: около 14 тыс. на 30 диалогов у Max (≈ 460 на диалог).

- **GigaChat-2-Max в 6 раз быстрее** Ollama на диалог (4,5 с против 26,3 с), **Lite — в 10 раз**.
- **Качество у Ollama чуть выше:** 98,8 % против 96,2 % (Max) и 93,4 % (Lite). На отложенном наборе: Ollama 97,5 %, Max 92,5 %, Lite 90,0 % при пороге проекта 90 %.
- **Без исправления фильтра** GigaChat находил только 81 % на отложенном наборе (результат сохранён в `loadtest/results_llm/old/`).

## 2. Общая скорость приложения под нагрузкой

Полный приём через API: вход, согласия, сигнализация, карточка, чат, речь обеих сторон каждые 10 с, расчёт лица, «Завершить приём», расшифровка, обезличивание, печать заключения. Пары говорят 60 с, затем очередь дорабатывается до конца. Порог «работает нормально» — как в прошлых отчётах. Скрипт `loadtest/run.py --llm ollama|gigachat`, облако — `GigaChat-2-Max`.

## Выводы

1. **Само обезличивание в облаке в 6 раз быстрее** (GigaChat-2-Max, 4,5 с на диалог против 26,3 с), качество немного ниже (96 % против 99 %), но выше порога проекта.
2. **На 1–2 парах приложение выдаёт готовый обезличенный текст через 6–8 с после завершения приёма вместо 1–2 минут** — в 11–13 раз быстрее.
3. **На 4–8 парах выигрыш меньше (1,5–4 раза), потому что узким местом становится расшифровка речи,** а не нейросеть: обезличивание ждёт, пока Whisper доделает текст. Отставание расшифровки одинаково превышает порог в обоих вариантах.
4. **Облако освобождает процессор для Whisper:** сервис речи получает в 1,3–3 раза больше процессорного времени (на 8 парах в среднем 667 % против 219 % одного ядра), отставание расшифровки на 8 парах снизилось на 16 % (128 с против 153 с).
5. **На 8 парах Ollama нарушает порог** готовности обезличивания (588 с при пороге 300 с), GigaChat укладывается (144 с).
6. **Что теряем:** главный принцип M.A.R.S. — «всё в локальной сети клиники, без облака». В облако уходит текст, в котором имена ещё не скрыты: это персональные медицинские данные. Для реальных пациентов это требует согласия на передачу, договора со Сбером и соответствия 152-ФЗ. Поэтому облачный режим оставлен выключенным по умолчанию и годится только для экспериментов на синтетических данных.

**Итог:** перенос обезличивания в GigaChat ускорил выдачу готового текста в 4–13 раз, в зависимости от нагрузки, и косвенно ускорил расшифровку речи. Дальнейший рост упирается в Whisper на 4 ядрах. Для реальной клиники выигрыш в скорости не перевешивает передачу необезличенного текста в облако; разумный компромисс — локальная модель на сервере клиники с видеокартой.

## Ограничения замера

- Каждая ступень и каждый вариант прогонялись по одному разу.
- Загрузку процессора самой Ollama замер не поймал: модель загрузилась уже после того, как он составил список процессов. Её доля видна косвенно — по тому, сколько процессора досталось расшифровке.
- Скорость облака зависит от сети и загрузки серверов Сбера в момент замера; у физлица один одновременный запрос, поэтому обезличивания разных пар идут по очереди (как и с Ollama).
- Стоимость не считалась: на тарифе Freemium токены бесплатные.
