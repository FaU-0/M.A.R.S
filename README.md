# M.A.R.S.

**Mobility & Asymmetry Reporting Sessions**: приложение для связи в локальной сети с функциями оценки подвижности лица, анализа асимметрии лица и составления отчётов по сеансу.

Видеосвязь врача и пациента, карточка и заметки, заключение с кодом МКБ-10 и модуль стандартизованной фотодокументации лица на базе MediaPipe Face Mesh, всё в одном Python-файле.

Сервер использует только стандартную библиотеку Python. Клиент написан на чистом JavaScript без сборки и зависимостей и вшит в `mars.py`. Интерфейс на русском языке.

> Модуль Face Mesh даёт числа для документирования, а не диагноз. Проект не является медицинским изделием и не заменяет очный осмотр.

## Возможности

### Консультация
- Запись на приём, ссылка и код для пациента, приглашение по email (если настроен SMTP).
- Согласие пациента, проверка камеры и микрофона перед входом, комната ожидания.
- Видеозвонок WebRTC (perfect negotiation, перезапуск ICE, повторное подключение), чат, передача файлов, демонстрация экрана.
- Обязательное указание адреса и телефона пациента до начала приёма (проверяется на сервере).
- Карточка пациента, приватные заметки врача, заключение с кодом МКБ-10 (справочник из 41 кода, формат кода проверяется на сервере), печать заключения.
- Кнопка экстренного завершения: комната закрывается, последующие запросы получают 410.
- Крупный шрифт, управление с клавиатуры, адаптивная вёрстка (компьютер, планшет, телефон).

### Face Mesh (фотодокументация лица)
- Анализ идёт на устройстве пациента. Видеопоток на сервер не отправляется и не сохраняется. Врачу передаются числа и снимки, которые пациент подтвердил сам.
- Отдельное согласие на анализ лица, которое можно отозвать в любой момент.
- Сетка или контуры поверх видео, подсказки по позе (расстояние, свет, наклон, неподвижность).
- Метрики симметрии: расстояния до средней линии, высота бровей и уголков рта, наклон линии глаз. Перед расчётом лицо приводится к анфасу по матрице преобразования MediaPipe, значения нормируются на межзрачковое расстояние.
- Подвижность лица по blendshapes (улыбка, брови, глаза, щёки, рот, губы). Это наблюдение для врача, а не клиническая шкала.
- Калибровка в миллиметрах по банковской карте (85,6 мм) или приблизительно по радужке. Без калибровки значения в мм не показываются и сервером не принимаются.
- Съёмка по ракурсам (анфас, 45, профиль) в максимальном разрешении камеры: удержание позы в допуске, отсчёт 3-2-1, предпросмотр, скрытие лица пикселизацией.
- Сравнение «до и после»: совмещение по методу Прокруста, шторка и наложение, стрелки смещения ключевых точек.
- Динамика между приёмами, отчёт для печати и PDF, выгрузка JSON.

### Чего в проекте нет намеренно
Пульс, SpO2, оценка эмоций, диагностические заключения, значения в мм без калибровки, метрики при позе вне допуска.

## Быстрый старт

Нужен Python 3.9 или новее.

```
python mars.py
```

При первом запуске в консоли один раз показывается пароль администратора (логин `admin`). Сохраните его. Откройте `http://localhost:8000`.

Файлы MediaPipe скачиваются автоматически в `DATA_DIR/vendor`. Если сети нет, в консоли будет список файлов с адресами: положите их вручную. Без этих файлов модуль Face Mesh отключается, а видеозвонок работает.

### Запуск в Jupyter
Выполните скрипт в ячейке: сервер запустится в фоновом потоке. Повторный запуск ячейки останавливает предыдущий экземпляр.

## Подключение пациента с другого устройства

Браузер разрешает камеру только на `https://` или `http://localhost`, поэтому по адресу `http://IP:8000` пациент камеру не включит. Два способа:

**Туннель (проще всего)**
```
cloudflared tunnel --protocol http2 --url http://localhost:8000
```
Туннель выдаст адрес `https://...trycloudflare.com`. Врач открывает его, пациент открывает тот же адрес с кодом: `https://...trycloudflare.com/?code=КОД`. Флаг `--protocol http2` нужен, если в сети режется UDP (QUIC).

**Собственный сертификат**
```
CERT_FILE=cert.pem KEY_FILE=key.pem python mars.py
```
В Windows PowerShell: `$env:CERT_FILE="cert.pem"; $env:KEY_FILE="key.pem"; python mars.py`. Пациент открывает `https://IP:8000/?code=КОД` и подтверждает предупреждение о самоподписанном сертификате. Сертификат должен содержать IP сервера в `subjectAltName`.

Для звонков через мобильные сети и разные NAT настройте TURN (`TURN_URL`, `TURN_SECRET`).

## Настройки

Все параметры задаются переменными окружения.

| Переменная | По умолчанию | Назначение |
|---|---|---|
| `PORT` | `8000` | Порт сервера |
| `DATA_DIR` | `aura_data` | База SQLite, файлы, снимки, `vendor/` |
| `AUTH_REQUIRED` | `True` | Требовать вход врача. `False` открывает функции врача без входа, только для отладки |
| `CERT_FILE`, `KEY_FILE` | пусто | Сертификат и ключ для HTTPS |
| `TURN_URL`, `TURN_SECRET` | пусто | TURN-сервер, временные учётные данные выдаются по схеме TURN REST |
| `SMTP_HOST`, `SMTP_PORT`, `SMTP_USER`, `SMTP_PASSWORD`, `SMTP_FROM` | пусто, порт `587` | Отправка приглашений на email |
| `CENTER_NAME` | `Медицинский центр` | Название центра в интерфейсе и документах |
| `MEDIAPIPE_VERSION` | `0.10.14` | Версия MediaPipe Tasks Vision для автозагрузки |

## Безопасность

- Пароли хранятся как scrypt-хэши, сессия в cookie, сравнение токенов через `hmac.compare_digest`.
- Ограничение частоты запросов (token bucket) по IP и по комнате, лимиты на размер JSON (25 МБ), файла (20 МБ) и снимка (5 МБ).
- Файлы принимаются только из белого списка типов с проверкой сигнатуры: PDF, JPEG, PNG, CSV, XLSX, XLS.
- Журнал аудита, заголовки CSP и защиты от встраивания, защита `/vendor` от обхода каталогов.
- Комнаты удаляются через 2 часа бездействия, в комнате хранится не более 500 событий.
- Сервер не принимает метрики с позой вне допуска и значения в мм без калибровки.

## Архитектура

- Сервер: `ThreadingHTTPServer` (HTTP/1.1), SQLite, сигнализация в памяти через `threading.Condition` и long polling до 20 с.
- Клиент: одностраничное приложение, DOM собирается функцией `h()` без `innerHTML`, общий цикл `requestAnimationFrame`, модули `Api`, `Rtc`, `Media`, `Poller`, `Session`, `CallUi`, `FaceMesh` и другие.
- Face Mesh: `FaceLandmarker` с blendshapes и матрицами преобразования, дерево подмодулей `Pose`, `Overlay`, `Symmetry`, `Mobility`, `Calibrate`, `Capture`, `Compare`, `Report`.

## API

Основные маршруты (формат ошибок: `{"error": "...", "message": "..."}`):

| Метод и путь | Назначение |
|---|---|
| `POST /rooms` | Создать комнату (201, `{room, token}`) |
| `POST /rooms/{room}/join` | Вход пациента (200, 404, 409, 410), повторный вход с тем же токеном идемпотентен |
| `POST` и `GET /rooms/{room}/events` | События (offer, answer, ice, chat, file, control, kill, ehr, document, presence, face, measure). `GET` принимает `after` и `wait` |
| `POST /rooms/{room}/frames` | JPEG-снимок, заголовок `X-Pose` |
| `GET` и `POST /rooms/{room}/protocol` | Протокол приёма, заключение, карточка |
| `POST /rooms/{room}/measurements` | Метрики Face Mesh |
| `GET /rooms/{room}/ice-config` | Настройки ICE и TURN |
| `/auth/*`, `/appointments`, `/patients`, `/photos/{id}`, `/audit`, `/health`, `/vendor/*` | Вход, приёмы, пациенты, снимки, аудит, служебное |

## Ограничения

1. Знак угла yaw и стороны blendshapes (правая и левая) проверены логикой и автопроверкой по положению носа. Их нужно сверить на реальной камере при вводе в эксплуатацию.
2. Face Mesh протестирован на синтетических ориентирах. Точность метрик на реальных лицах и скорость на слабых устройствах не подтверждены.
3. MediaPipe не отслеживает профиль 90 градусов: такие снимки делаются только вручную, без контроля позы и метрик.
4. Снимки со скрытым лицом нельзя сравнивать. Скрытие идёт по контуру последнего найденного кадра, при резком движении край лица может остаться видимым.
5. Миллиметры доступны только в анфасе и только после калибровки. Калибровка по радужке приблизительная (радужка принята за 11,7 мм).
6. Согласие на анализ лица хранится на устройстве пациента и передаётся врачу событием, сервер при входе его не проверяет.
7. После аварийного завершения сохранение в протокол прекращается.
8. Без TURN звонок может не соединиться в мобильных сетях и за строгими NAT.
9. Проект не проходил аудит безопасности и не сертифицирован как медицинское изделие. Для реальных пациентов нужна отдельная оценка требований по персональным данным.
