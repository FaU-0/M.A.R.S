# M.A.R.S.

**Mobility & Asymmetry Reporting Sessions**: приложение для связи в локальной сети с функциями оценки подвижности лица, анализа асимметрии лица и составления отчётов по сеансу.

Видеосвязь врача и пациента, карточка и заметки, заключение с кодом МКБ-10 и модуль стандартизованной фотодокументации лица на базе MediaPipe Face Mesh. Приложение состоит из нескольких независимых сервисов: отказ любого вторичного сервиса не останавливает звонок и запись приёма.

Интерфейс на русском языке. Основной сервер (`gateway`) использует только стандартную библиотеку Python, клиент написан на чистом JavaScript без сборки и вшит в `gateway/mars.py`.

> Модуль Face Mesh даёт числа для документирования, а не диагноз. Проект не является медицинским изделием и не заменяет очный осмотр.

## Состояние разработки

Проект переводится с одного файла на набор сервисов по этапам.

| Этап | Что | Статус |
|---|---|---|
| 0 | Каркас: `shared`, `run_all.py`, `/health`, `/ready`, `/status`, индикатор в интерфейсе | сделано |
| 1 | `reports`: печатная форма заключения, запасная печать в браузере | сделано |
| 2 | `vision`: метрики симметрии, подвижности, сравнение до и после, калибровка | сделано |
| 3 | `speech`: запись кусков речи и расшифровка Whisper | сделано |
| 4 | `assistant`: обезличивание расшифровки через локальную Ollama, вкладка «Расшифровка» | сделано |
| 5 | Тест остановки каждого сервиса по очереди на полном наборе | сделано |
| 6 | `database`: вынос SQL из gateway в отдельный сервис, миграции, резервные копии | сделано |

Точки лица находит браузер (MediaPipe в браузере), сервис `vision` считает по ним метрики. Если на компьютере установлен MediaPipe для Python, `vision` сам находит точки по снимку. Отчёт по лицу (графики, снимки) строится в браузере.

## Возможности

### Консультация
- Запись на приём, ссылка и код для пациента, приглашение по email (если настроен SMTP).
- Согласие пациента, проверка камеры и микрофона перед входом, комната ожидания.
- Видеозвонок WebRTC (perfect negotiation, перезапуск ICE, повторное подключение), чат, передача файлов, демонстрация экрана.
- Обязательное указание адреса и телефона пациента до начала приёма (проверяется на сервере).
- Карточка пациента, приватные заметки врача, заключение с кодом МКБ-10 (справочник из 41 кода, формат кода проверяется на сервере), печать заключения.
- Кнопка экстренного завершения: комната закрывается, последующие запросы получают 410.
- Режим «Крупно и контрастно» для слабовидящих (крупнее текст и элементы, выше контраст; кнопка на первом экране пациента и в меню), управление с клавиатуры, адаптивная вёрстка (компьютер, планшет, телефон).
- Русский и английский интерфейс: переключатель в меню и на первых экранах пациента, или `?lang=en` в ссылке. Выбор запоминается в браузере. Строки пишутся по-русски через `T('...')`, переводы лежат в `gateway/src/c_i18n.js` (словарь `EN`); тест `python tests/test_i18n.py` находит строки без перевода. Печатное заключение сервис `reports` строит на языке интерфейса; текст, который написал врач, не переводится.

### Face Mesh (фотодокументация лица)
- Анализ идёт на устройстве пациента. Видеопоток на сервер не отправляется и не сохраняется. Врачу передаются числа и снимки, которые пациент подтвердил сам.
- Отдельное согласие на анализ лица, которое можно отозвать в любой момент.
- Сетка или контуры поверх видео, подсказки по позе (расстояние, свет, наклон, неподвижность).
- Метрики симметрии: расстояния до средней линии, высота бровей и уголков рта, наклон линии глаз. Перед расчётом лицо приводится к анфасу по матрице преобразования MediaPipe, значения нормируются на межзрачковое расстояние.
- Подвижность лица по blendshapes (улыбка, брови, глаза, щёки, рот, губы). Это наблюдение для врача, а не клиническая шкала.
- Калибровка в миллиметрах по банковской карте (85,6 мм) или приблизительно по радужке. Без калибровки значения в мм не показываются и сервером не принимаются.
- Проверка повторяемости: серия из 3, 5 или 10 замеров симметрии подряд. Для каждой метрики считаются среднее, стандартное отклонение (SD) и минимальное различимое изменение MDC95 = 1,96·√2·SD; таблицу можно скачать в CSV. Тест: `python tests/test_repeat.py`.
- Экспорт отчёта по лицу в HL7 FHIR R4: Bundle типа collection с Patient (идентификатор клиники) и Observation на каждую метрику; правая и левая сторона и разность — компоненты наблюдения, единицы UCUM (`mm` с калибровкой, `1` для долей МЗР, `deg` для углов), коды из системы `urn:mars:face-metric` (кодов LOINC для этих метрик нет). Тест: `python tests/test_fhir.py`.
- Съёмка по ракурсам (анфас, 45, профиль) в максимальном разрешении камеры: удержание позы в допуске, отсчёт 3-2-1, предпросмотр, скрытие лица пикселизацией.
- Сравнение «до и после»: совмещение по методу Прокруста, шторка и наложение, стрелки смещения ключевых точек.
- Динамика между приёмами, отчёт для печати и PDF, выгрузка JSON.
- Метрики считает сервис `vision`. Если он недоступен или не ответил за 6 секунд, браузер считает сам по тем же формулам и показывает об этом сообщение.

### Расшифровка и обезличивание
- Расшифровка включается только после отдельного согласия пациента; пациент может отозвать его нажатием на индикатор «Идёт расшифровка речи».
- Каждая сторона записывает свой микрофон кусками по 10 секунд, поэтому реплики врача и пациента разделяются сами. Аудио удаляется сразу после расшифровки, исходный текст хранится 30 дней.
- По команде «Завершить приём» расшифровка обезличивается в три шага: данные из карточки и имя врача, правила (телефоны, документы, даты, адреса, словари имён и городов), локальная нейросеть Ollama. Модель только называет фрагменты, заменяет их код.
- Вкладка «Расшифровка» у врача: текст с метками (`[ФИО_ПАЦИЕНТА]`, `[ИМЯ_1]`, `[МЕСТО_1]`...), отмена и добавление замен, «Показать оригинал» (записывается в журнал аудита), «Обезличить повторно», подтверждение для отчёта.
- Ограничения расшифровки: речь распознаётся только на русском (в английском интерфейсе тоже, об этом предупреждает вкладка «Расшифровка»); куски по 10 секунд режутся по таймеру, а не по паузам, поэтому слова на стыках иногда теряются; модель Whisper `small` на процессоре без словаря медицинских терминов. Текст в любом случае проверяет врач перед отчётом.
- В отчёт сеанса (раздел «Ход консультации») и выгрузку JSON попадает только обезличенный текст, проверенный врачом.

## Быстрый старт

Нужен Python 3.9 или новее. Для расшифровки и обезличивания нужны ещё две вещи (без них звонок, Face Mesh и печать работают):

```
python3 -m venv speech/.venv
speech/.venv/bin/pip install -r speech/requirements.txt
```

Это окружение сервиса `speech` (faster-whisper); `run_all.py` находит его сам. Модель Whisper скачивается при первом запуске в `MODELS_DIR`. Для `assistant` установите [Ollama](https://ollama.com) и скачайте модель: `ollama pull qwen2.5:3b`.

```
python run_all.py
```

Команда запускает все сервисы и перезапускает упавший. Можно запустить не всё:

```
python run_all.py --without speech,assistant
python run_all.py --only gateway,reports
```

Основной сервер можно запустить и отдельно, как раньше: `python gateway/mars.py`. Тогда вторичных сервисов нет, `/status` всегда отвечает `ok`, печать заключения идёт из браузера, а база открывается внутри gateway тем же кодом, что и в сервисе `database` (папка `database/` должна лежать рядом с `gateway/`).

Логин и пароль администратора выводятся в консоль при каждом запуске (логин `admin`). Пароль сохраняется в `DATA_DIR/admin_password.txt`: ограничьте доступ к этой папке и смените пароль через `ADMIN_PASSWORD` перед реальным использованием. Откройте `http://localhost:8000`.

Файлы MediaPipe скачиваются автоматически в `DATA_DIR/vendor`. Если сети нет, в консоли будет список файлов с адресами: положите их вручную. Без этих файлов модуль Face Mesh отключается, а видеозвонок работает.

### Запуск в Jupyter
Выполните `gateway/mars.py` в ячейке: сервер запустится в фоновом потоке. Повторный запуск ячейки останавливает предыдущий экземпляр. Вторичные сервисы в Jupyter запускаются отдельно через `run_all.py`.

## Подключение пациента с другого устройства

Браузер разрешает камеру только на `https://` или `http://localhost`, поэтому по адресу `http://IP:8000` пациент камеру не включит. Два способа:

**Туннель (проще всего)**
```
cloudflared tunnel --protocol http2 --url http://localhost:8000
```
Туннель выдаст адрес `https://...trycloudflare.com`. Врач открывает его, пациент открывает тот же адрес с кодом: `https://...trycloudflare.com/?code=КОД`. Флаг `--protocol http2` нужен, если в сети режется UDP (QUIC).

**Собственный сертификат**
```
CERT_FILE=cert.pem KEY_FILE=key.pem python run_all.py
```
В Windows PowerShell: `$env:CERT_FILE="cert.pem"; $env:KEY_FILE="key.pem"; python run_all.py`. Пациент открывает `https://IP:8000/?code=КОД` и подтверждает предупреждение о самоподписанном сертификате. Сертификат должен содержать IP сервера в `subjectAltName`.

Для звонков через мобильные сети и разные NAT настройте TURN (`TURN_URL`, `TURN_SECRET`).

## Безопасность

- Врач видит пациента (поиск, снимки, измерения, история) только через свой приём; администратор видит всех. Записать к себе на приём чужого пациента нельзя, неназначенный приём раздаёт администратор. Снимки приёма, у которого ещё нет карточки, видит только врач этого приёма; когда карточка появляется, снимки и измерения привязываются к пациенту. Чужой пациент неотличим от несуществующего (404), каждая попытка пишется в журнал аудита.
- Папка данных доступна только владельцу: `DATA_DIR` 0700, база, снимки, файлы и аудио 0600.
- Отзыв согласия на расшифровку удаляет куски речи, которые ещё не расшифрованы, вместе с аудио. После завершения приёма (обычного или экстренного) запись не включается и куски не принимаются.
- В журналах сервисов нет текста расшифровки и ответов нейросети.
- У каждого врача своя ссылка в комнату, она действует только вместе с его сессией: после выхода ссылка перестаёт работать. В журнале аудита логин врача; записываются просмотры карточки, истории пациента, файлов, обезличенного текста, исходной расшифровки, поиск пациентов (без текста запроса) и печать заключения.
- Лимиты на приём: файлы до `APPT_FILES_MB` (200 МБ), снимков `APPT_PHOTOS` (300), измерений `APPT_MEASUREMENTS` (500), кусков речи в очереди `APPT_QUEUED_AUDIO` (720). Если на диске меньше `MIN_FREE_MB` (500 МБ), загрузки не принимаются (507).
- Измерение лица хранит, кто его прислал (`submitted_by`) и проверено ли оно сервером (`verified`): если метрики посчитал `vision`, сохраняются его числа, а не присланные браузером.
- Сохранённый отчёт по лицу не хранит текст расшифровки, только отметку, что она была включена. Задание, не выполненное за сутки, помечается ошибкой (а не удаляется молча), его входные данные стираются, врач видит, что расшифровка неполная.
- Пароли врачей хранятся как scrypt-хэши (пароль администратора дополнительно лежит в файле `admin_password.txt`), сессия в cookie, сравнение токенов через `hmac.compare_digest`.
- Ограничение частоты запросов (token bucket) по IP и по комнате, лимиты на размер JSON (25 МБ), файла (20 МБ) и снимка (5 МБ).
- Файлы принимаются только из белого списка типов с проверкой сигнатуры: PDF, JPEG, PNG, CSV, XLSX, XLS.
- Журнал аудита, заголовки CSP и защиты от встраивания, защита `/vendor` от обхода каталогов.
- Комнаты удаляются через 2 часа бездействия, в комнате хранится не более 500 событий.
- Сервер не принимает метрики с позой вне допуска и значения в мм без калибровки.

## Архитектура

| Сервис | Порт | Задача |
|---|---|---|
| gateway | 8000 | Интерфейс, вход, комнаты и сигнализация, приёмы и пациенты (данные в `database`), очередь заданий для вторичных сервисов. Единственный сервис, доступный из сети |
| vision | 8001 | Метрики по точкам лица: симметрия, подвижность, сравнение до и после, калибровка |
| reports | 8002 | Печатные формы заключений и отчётов |
| speech | 8003 | Whisper: кусок речи в текст. Своё окружение `speech/.venv` |
| assistant | 8004 | Обезличивание расшифровки: правила и Ollama |
| database | 8005 | SQLite: схема и миграции, все запросы, хранение очереди заданий, резервные копии |

Gateway SQL не содержит: все запросы лежат в `database/queries.py` под именами (`appointments.by_id`, `jobs.due`...), gateway вызывает их через `POST /v1/q {name, args}`. Произвольный SQL сервис не принимает. Схема меняется только новым шагом в `database/schema.py`, номер применённого шага хранится в таблице `schema_version`; база, созданная прежним gateway, обновляется при первом запуске без потери данных.

Вторичные сервисы, кроме `database`, состояния не хранят. Задания для них (расчёты лица, куски речи, обезличивание) лежат в таблице `jobs` (сервис `database`), очередь ведёт gateway: задания переживают перезапуск, повторяются с нарастающей паузой, повтор с тем же ключом не создаёт дубля. У каждого сервиса свой поток очереди, поэтому зависший сервис не задерживает остальные.

- Сервисы общаются только по HTTP API. Вторичные сервисы (включая `database`) слушают `127.0.0.1` и принимают запросы только с HMAC-подписью общего секрета (`X-MARS-Sig`, `X-MARS-Ts`), кроме `/health` и `/ready`.
- Вызовы между сервисами идут через клиент из `shared/` с таймаутом и выключателем цепи: после трёх ошибок подряд запросы к сервису не шлются, раз в несколько секунд проходит пробный.
- Единый формат ошибок: `{"error": "...", "message": "...", "service": "..."}`. При отказе сервиса gateway отвечает `503` с `Retry-After` и `"degraded": true`.
- `GET /status` в gateway собирает `/ready` всех сервисов и возвращает `ok` или `degraded`. Если сервис недоступен, в шапке интерфейса появляется индикатор.
- Сервер (gateway): `ThreadingHTTPServer`, сигнализация в памяти через `threading.Condition` и long polling до 20 с. База SQLite в сервисе `database`.
- Клиент: одностраничное приложение, DOM собирается функцией `h()` без `innerHTML`, модули `Api`, `Rtc`, `Media`, `Poller`, `Session`, `CallUi`, `FaceMesh` и другие.

### Что работает, когда сервис упал

| Упал | Продолжает работать | Что видит пользователь |
|---|---|---|
| reports | Всё остальное | Печать заключения идёт из браузера |
| vision | Звонок, чат, живая сетка в браузере. Расчёт ставится в очередь | Метрики считает браузер, сообщение «Анализ временно недоступен» |
| speech | Звонок, заметки, анализ лица. Куски речи ждут на диске | Индикатор: куски сохранены, расшифровка догрузится сама |
| assistant | Всё, включая расшифровку. Исходный текст сохранён | Обезличивание ждёт; в отчёт текст не попадает, пока не обезличен и не проверен |
| database | Идущий звонок (сигнализация WebRTC в базу не ходит), индикатор состояния | Остальные действия отвечают 503 «База данных временно недоступна» за несколько секунд, без зависания. `run_all.py` поднимает упавший сервис заново |
| gateway | Вторичные сервисы, идущий звонок | Новые подключения невозможны: это единственная точка отказа. `run_all.py` поднимает gateway заново, очередь заданий дорабатывается |

Каждая строка таблицы проверяется тестом `tests/test_failover.py`.

## API

Основные маршруты (формат ошибок: `{"error": "...", "message": "..."}`):

| Метод и путь | Назначение |
|---|---|
| `POST /rooms` | Создать комнату (201, `{room, token}`) |
| `POST /rooms/{room}/join` | Вход пациента (200, 404, 409, 410), повторный вход с тем же токеном идемпотентен |
| `POST` и `GET /rooms/{room}/events` | События (offer, answer, ice, chat, file, control, kill, ehr, document, presence, face, measure). `GET` принимает `after` и `wait` |
| `POST /rooms/{room}/frames` | JPEG-снимок, заголовок `X-Pose` |
| `POST /rooms/{room}/render-conclusion` | Печатная форма заключения (через сервис reports, 503 при его отказе) |
| `GET /status` | Состояние вторичных сервисов: `ok` или `degraded` |
| `GET` и `POST /rooms/{room}/protocol` | Протокол приёма, заключение, карточка |
| `POST /rooms/{room}/measurements` | Метрики Face Mesh |
| `POST /rooms/{room}/analyze` | Расчёт в `vision` через очередь (202 и номер задания; 503, если `vision` не подключён) |
| `GET /rooms/{room}/jobs/{id}` | Состояние задания и результат |
| `POST /rooms/{room}/audio` | Кусок записи своего микрофона (только при согласии пациента), заголовки `X-Chunk-Key`, `X-Seq`, `X-Duration-Ms`, `X-Offset-Ms` |
| `GET /rooms/{room}/transcript` | Обезличенная расшифровка (только врач); `/status` - сколько кусков расшифровано; `/original` - исходник с записью в аудит |
| `POST /rooms/{room}/transcript/deidentify`, `/transcript/edit` | Обезличить повторно; правки врача: `undo`, `add`, `confirm`, `unconfirm` |
| `GET /rooms/{room}/ice-config` | Настройки ICE и TURN |
| `/auth/*`, `/appointments`, `/patients`, `/photos/{id}`, `/audit`, `/health`, `/vendor/*` | Вход, приёмы, пациенты, снимки, аудит, служебное |

## Ограничения

1. Знак угла yaw и стороны blendshapes (правая и левая) проверены логикой и автопроверкой по положению носа. Их нужно сверить на реальной камере при вводе в эксплуатацию.
2. Face Mesh протестирован на синтетических ориентирах. Точность метрик на реальных лицах и скорость на слабых устройствах не подтверждены.
3. MediaPipe не отслеживает профиль 90 градусов: такие снимки делаются только вручную, без контроля позы и метрик.
4. Снимки со скрытым лицом нельзя сравнивать. Скрытие идёт по контуру последнего найденного кадра, при резком движении край лица может остаться видимым.
5. Миллиметры доступны только в анфасе и только после калибровки. Калибровка по радужке приблизительная (радужка принята за 11,7 мм).
6. Согласие на анализ лица хранится на устройстве пациента и передаётся врачу событием, сервер при входе его не проверяет.
7. После аварийного завершения сохранение в протокол прекращается.
8. Без TURN звонок может не соединиться в мобильных сетях и за строгими NAT.
9. Проект не проходил аудит безопасности и не сертифицирован как медицинское изделие. Для реальных пациентов нужна отдельная оценка требований по персональным данным.
10. Обезличивание не гарантирует ста процентов: малая модель на процессоре пропускает часть имён и названий, а редкий диагноз вместе с возрастом может раскрыть человека без имени. Поэтому текст попадает в отчёт только после проверки врачом.
11. Whisper ошибается в названиях препаратов. Расшифровка и обезличивание проверены на синтезированной речи и синтетических диалогах, а не на записях живых консультаций.
12. Расшифровку врач видит на экране приёма сразу после «Завершить приём»; завершённый приём, как и заключение, заново не открывается.
13. MediaPipe для Python не ставится на Mac с Intel и Python 3.12, поэтому точки лица находит браузер. Поиск точек на сервере (`vision/detector.py`) не проверен.

## Структура репозитория

```
gateway/
  mars.py        основной сервер и клиент (собирается из src/ командой build.sh)
  src/           исходники: a1_core … a7_main.py (сервер: настройки, данные, HTTP, комнаты, клинические разделы, очередь, запуск), b_head.html, c_i18n.js (переводы), c_js*.js, d_face*.js, e_speech.js, f_transcript.js

assistant/       обезличивание: правила (deid.py) и Ollama (main.py)

contracts/       схемы запросов и ответов сервисов (будут добавлены)
tests/           проверка отказов, метрик, расшифровки, обезличивания; синтетические диалоги
run_all.py       запуск всех сервисов одной командой
README.md        это описание
```
